Лабораторная работа 3
Лабораторная работа: Форма обратной связи с валидацией и 
состояниями в React

Цель работы
Научиться управлять состоянием формы в React с помощью хука useState, реализовать 
клиентскую валидацию полей и стилизовать различные состояния полей (покой, фокус, 
ошибка, успех).
Теоретическая справка
Хук useState — это функция React, которая позволяет функциональному компоненту хранить и 
обновлять локальное состояние. Возвращает массив из двух элементов: текущего значения и 
функции-сеттера.
jsx
const [value, setValue] = useState(initialValue);
Управляемые компоненты — поля формы, значение которых контролируется React-состоянием. 
Каждый ввод символа обновляет состояние, а состояние определяет отображаемое значение.
Валидация — проверка данных перед отправкой. В React обычно реализуется в двух моментах:
при изменении поля (on-the-fly);
при отправке формы (on submit).
Состояния полей — визуальные подсказки пользователю: 
покой (idle), фокус (focus), ошибка (error), успех (valid).

Оператор spread (...) в JavaScript (комментарий)
Оператор spread (...) в JavaScript — это синтаксический сахар, который «распаковывает» элементы массива или свойства объекта в 
другой контекст. 
Разберём, как это работает:
Для объектов (как в handleChange).
В строке ...prev оператор spread копирует все текущие свойства объекта prev в новый объект:
Пример
const prev = { name: 'Alex', age: 25, city: 'Moscow' };
const next = {  ...prev,
  age: 26,                // обновляем существующее свойство
  job: 'developer'         // добавляем новое
};
console.log(next);
// Результат: { name: 'Alex', age: 26, city: 'Moscow', job: 'developer' }
Почему это критично в React:
•
 состояние нельзя менять напрямую (мутировать).
•
 Spread позволяет создать новый объект с нужными изменениями, сохранив при этом все остальные данные.
 Именно поэтому в setFormData используют паттерн prev => ({ ...prev, ... }) — он гарантирует, что мы не потеряем остальные 
поля формы.

Шаг 2. Функции валидации
Добавим функции для проверки каждого поля. Поместите их внутри компонента, перед return.
// --- Функции валидации ---
  // Имя: минимум 2 символа, только буквы, пробелы и дефис.
  const validateName = (value) => {
if (!value.trim()) return "Имя обязательно для заполнения";
if (value.trim().length < 2) return "Минимум 2 символа";
if (!/^[a-zA-Zа-яА-ЯёЁ\s-]+$/.test(value.trim()))
return "Только буквы, пробелы и дефис";
    return null; // нет ошибки
  };
  // Email: проверка через регулярное выражение.
  const validateEmail = (value) => {
if (!value.trim()) return "Email обязателен для заполнения";
// Простая, но достаточно надёжная проверка формата.
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value.trim()))
return "Некорректный формат email";
return null;
};
•! — логическое «НЕ»: результат совпадения инвертируется. В 
коде это обычно выглядит как !regex.test(email), то есть 
«если тест НЕ прошёл — считаем адрес невалидным».
•/ ... / — ограничители регулярного выражения (синтаксис 
JS).
•^ — начало строки.
•[^\s@]+ — один или более символов, которые не являются 
пробелом (\s) и не являются @. Это «локальная часть» адреса 
(до @).
•@ — обязательный символ «собака».
•[^\s@]+ — снова один или более символов, не являющихся 
пробелом и @ (доменная часть до точки).
•\. — экранированная точка (разделитель домена и зоны).
•[^\s@]+ — один или более символов после точки (доменная 
зона).
•\$ — конец строки.
Итого шаблон требует структуру: локальная_часть@домен.зона, 
где ни в одной части нет пробелов и лишних @.

Шаг 4. Обработчик потери фокуса (blur)
При выходе из поля помечаем его как 
тронутое и проводим валидацию.
// Обработчик потери фокуса.
  const handleBlur = (field) => {
    // Помечаем поле как тронутое.
    setTouched((prev) => ({ ...prev, [field]: true 
}));
    // Получаем текущее значение поля.
    const currentValue =
      field === "name" ? name : field === "email" 
? email : message;
// Валидируем и записываем результат.
    setErrors((prev) => ({
      ...prev,
[field]: validators[field](currentValue),
}));
};

Шаг 5. Обработчик отправки формы
// Обработчик отправки формы.
  const handleSubmit = (e) => {
    e.preventDefault(); // Предотвращаем 
перезагрузку страницы.
    // 1. Валидируем все поля сразу.
    const newErrors = {
      name: validateName(name),
email: validateEmail(email),
message: validateMessage(message),
    };
    // 2. Записываем ошибки и помечаем все 
поля как тронутые.
    setErrors(newErrors);
setTouched({ name: true, email: true, 
message: true });
// 3. Если хотя бы одна ошибка есть — не отправляем.
    if (Object.values(newErrors).some((err) => err !== null)) {      
return; // Прерываем отправку.    }
    // 4. Имитируем отправку на сервер.
    setIsSubmitting(true);
    // setTimeout имитирует сетевой запрос с задержкой 1.5 
секунды.
    setTimeout(() => {
setIsSubmitting(false);
setSubmitted(true);
// В реальном проекте здесь был бы fetch / axios:
      // fetch("/api/feedback", { method: "POST", body: ... })
}, 1500);
};
